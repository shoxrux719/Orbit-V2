# ORBIT Campus 2.0

Три кабинета с отдельной навигацией и проверкой доступа на сервере.

- Администрация: Control center, люди и доступ, группы, программа Navigate,
  файлы центра, данные и отчёты, Campus studio, история действий.
- Учитель: Home, Lessons, Ranking, Tasks, Exams, Library, Vocabulary.
- Ученик: Home, Lessons, Practice, Marks, Ranking, Extra lesson.

## Программа Navigate

Подготовлены маршруты A1 Beginner, A2 Elementary, B1 Pre-intermediate.
По 36 черновиков с номерами 1.1–12.3 — изменяемая заготовка структуры,
а не утверждение о содержании конкретного издания Oxford. Можно добавлять юниты.
Тексты, аудио и видео книги не включены: владелец пока не предоставил материалы.

1. Администратор задаёт уровень ученика при создании аккаунта. Поменять его
   можно в «Люди и доступ» → «Управление» → «Уровень».
2. В «Программа Navigate» выбирает уровень и юнит, указывает тему и издание,
   добавляет объяснения, Vocabulary, прямую HTTPS-ссылку на видео и упражнения.
   На каждом этапе нужны вопросы с вариантами и правильным ответом.
3. Публикует юнит. До публикации ученики видят закрытую карточку своего маршрута.
4. Учитель в Tasks назначает юнит группе, дату занятия и срок. Уровни группы,
   юнита и ученика должны совпадать. Состав групп меняет только администрация.
5. Ученик открывает домашку с Home. Этапы Vocabulary → Video lesson → Practice
   открываются последовательно. Дополнительно можно добавить Listening/Reading.

Редактор также принимает JSON с полями title, edition, steps. Структура этапа:

```json
{
  "type": "vocabulary",
  "skill": "vocabulary",
  "title": "Vocabulary",
  "instructions": "Слова и объяснения из ваших материалов",
  "mediaUrl": "",
  "questions": [
    {
      "prompt": "Ваш вопрос",
      "options": ["Верный ответ", "Другой вариант"],
      "answer": 0,
      "explanation": "Объяснение после верного ответа"
    }
  ]
}
```

Обычный редактор не требует JSON. Выданный юнит фиксируется: материал и количество
вопросов нельзя поменять задним числом, чтобы не повредить результаты учеников.
Для нового материала создайте отдельный юнит.

## Баллы и журнал

Процент домашки = количество верно решённых вопросов / все вопросы юнита × 100,
с округлением вниз. Ошибочный ответ можно исправить. Верный вопрос учитывается
один раз. Проверка и порядок этапов контролируются сервером; браузер не присылает
готовую оценку. Баллы = сумма процентов по домашкам, до 100 за юнит. Автоматические
коины = целая часть процента / 5, до 20 за юнит.

Игры и прежние ручные оценки не увеличивают новые баллы. Экзамены назначаются
в Exams и сохраняют отдельный прогресс, без влияния на баллы домашки.
Проценты видны в месячном журнале учителя и в Marks ученика. Ученик видит свои
результаты; учитель — результаты своих групп. Посещаемость отмечается отдельно.
Рейтинг групп — средний процент выполнения назначенной домашки всех активных
учеников группы, включая нулевые результаты ещё не начатых работ.

Старые записи не удаляются. Их можно прочитать в группе во вкладке «История до
Navigate». Ранее заработанные коины зафиксированы миграцией как начальный кредит;
существующие заказы продолжают вычитаться из баланса.

## Сопровождение и коины

Home учителя показывает Active, New (созданы за 7 дней), Lost, Potential fail,
Absent today (по местной дате Ташкента), Red list, Black list. Статусы сопровождения
задаются сотрудником с причиной; они не отключают аккаунт автоматически.
Lost/Black list задаёт и снимает только администрация.

В карточке своего ученика учитель может выдать 1–500 коинов, указав причину и
личный пароль. Дневной лимит — 5000, сутки по UTC. Есть ограничение попыток пароля,
повтор запроса с тем же номером операции не начисляет награду повторно.
Коины не увеличивают учебный рейтинг. Выдачи сохраняются в журнале и истории коинов.

Library и Vocabulary наполняет администрация. «Файлы центра» хранит защищённый
реестр ссылок на документы; сами файлы остаются в выбранном облачном хранилище.
«Данные и отчёты» выгружает учебный JSON без паролей, телефонов и сессий.

## Запуск и проверки

```powershell
npm run design:build
npm run db:migrate
npm start
npm test
npm run test:vercel
```

Новые исходники: design/academy.jsx, academy.css, academy-data.js,
academy-server.js, navigate-schema.sql, wallet-opening.sql.
Миграции 0008 и 0009 добавляют таблицы и фиксируют начальный кошелёк без удаления
старых данных. Production: npm run production:setup с локальным игнорируемым
.env.production.local, затем обычное развёртывание Vercel.

Для полной локальной проверки с отдельными тестовыми аккаунтами и авторскими
вопросами, не выдаваемыми за содержание Navigate:

```powershell
node design/live-academy-check.mjs
node design/live-academy-check.mjs --cleanup
```

На Node ниже 22 используйте bundled Node Codex. Скрипт рассчитан только на
127.0.0.1:3000. Данные тестовых аккаунтов сохраняются в игнорируемом
design/.academy-qa.json. Очистка удаляет только созданные этим запуском записи.
